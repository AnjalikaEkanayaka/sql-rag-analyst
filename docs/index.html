SQL + RAG Analyst

Ask a plain-English question about a database. The system finds the relevant tables, has an LLM write read-only SQL, validates it with a parser-based guard, runs it, and explains the result.

Source code on GitHub · Demo video: coming soon

About this page

There is no live backend here, on purpose. The project needs a Python server and a rate-limited free LLM API, and Hugging Face now requires a paid plan to create Docker Spaces. So this page shows real recorded outputs from the pipeline, each one checked automatically against a verified answer. You can run the live system yourself in a few commands (bottom of the page).

How it works

1. RetrieveRAG over a data dictionary: embeddings pick the relevant tables
→
2. GenerateAn LLM writes one SQLite SELECT from those tables
→
3. Guard & runsqlglot validation, read-only connection, row cap, timeout, logging
→
4. ExplainA short plain-English answer next to the SQL

The same pipeline is exposed as an MCP server (for AI agents) and a FastAPI service, and evaluated on 40 questions with verified gold SQL.

Safety design

  • The SQL is parsed with sqlglot: exactly one SELECT, nothing else (no INSERT, UPDATE, DELETE, DROP, ALTER, PRAGMA, ATTACH).
  • Only known tables; dangerous functions blocked; system tables and table-valued functions rejected.
  • A LIMIT is enforced, with a timeout and a row cap; the database is opened read-only.
  • The question is treated as data, never as instructions; every query is logged.
  • Around 30 attack cases and the rest of the guard are covered by automated tests.

Limitations

  • Chinook is small (11 tables) and public. The unrestricted accuracy partly came from table names that the prompt's foreign-key lines revealed, so the strict numbers are the conservative ones.
  • Most failures were retrieval misses: tables mentioned only through values ("Jazz", "AC/DC") or actions ("bought").
  • Generated SQL can be wrong without any error. Always read the SQL shown next to an answer.
  • No authentication or rate limiting yet, so it is not meant to be exposed publicly as is.

Run it yourself

git clone https://github.com/AnjalikaEkanayaka/sql-rag-analyst
cd sql-rag-analyst
python -m venv .venv && .venv/Scripts/activate      # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
# put GROQ_API_KEY=... in a .env file (free key from console.groq.com)
python -m src.retrieval build
python -m uvicorn src.api:app --port 8000               # open http://localhost:8000/docs
